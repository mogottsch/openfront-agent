# Credible one-send nation conquest is not a reserve-ratio guarantee

Moritz's goal is to attack a native nation only with a credible whole-conquest plan, ideally in one send, after finishing bordering tribes. This note supplies **engine mechanics counterexamples**, not a replacement strategy, a hard army-ratio gate, or a model win. `scripts/analyze-nation-one-send.mts` makes exactly **one human land attack** at 10/20/30/40/50% of available troops per controlled case. It never reinforces, cancels, builds for the human, requests Jev/Copilot, or starts a browser. This study does not edit the sibling OpenFront checkout. Source commit: `bb8af015b515b3b717bd4d901074c5f4c16641cb`.

```sh
../OpenFrontIO/node_modules/.bin/tsx --tsconfig ../OpenFrontIO/tsconfig.json scripts/analyze-nation-one-send.mts
```

The bounded, deterministic report is ignored `logs/nation-one-send.json`. Two final repeats with `globalThis.fetch` replaced by an immediate `NETWORK_FORBIDDEN` error produced byte-identical JSON (SHA-256 `5553df22416279feb93eead229946c830b44cd6ec95cfa43fbe279f8b512dcfe`). It records the exact send, actual initial target reserve, terrain, completed Post, hostility at initialization, live target/attack progress, actual conquest event/gold transfer, and native queued **and observed** counterattacks separately. These are **prepared combat trials, not full matches**: a conquest is a target elimination event, not an OpenFront WinCheck victory.

## Controlled cases and limits

The passive matrix has **160 cases**: nation starting territory **80, 100, 500 or 2,000 tiles** × reserve **50,000 or 150,000 internal troops** × no Post/one completed defender Post × plains/mountain target terrain × five send fractions. Another five passive cases use 2,000 tiles/300,000 target reserve; **20** separately labelled cases enable real `NationExecution` with the same fixed game/player IDs and matching terrain/armies for comparisons. Total **185** bounded trials. The prepared human has 2,500 plains tiles and **300,000 internal troops** immediately before its one send; troop values divide by ten for game display. No third player, existing tribe, wilderness, water route, City, fallout, counter-diplomacy or API latency is involved. This is a possible *post-tribe resource state*, not a simulated preceding tribe economy.

Each fresh 256×256 map is impassable outside two touching passable rectangles. `PlayerExecution` applies genuine growth on both sides. A Post is **worker-legal** at the desired defender site, financed with exactly 50,000 extra setup gold, then built through the same trusted `ConstructionExecution` used by native nation structure behavior. It finishes before combat; its temporary funding has been spent, leaving the same worker-earned wallet as the no-Post control. Nations have no human clientID, so the script does **not** pretend that a stamped human build intent authorizes the nation's Post. All games take equal setup turns, and troop reserves are reset identically immediately before the single normal stamped human attack. Native-AI cases first let its unconditional initial wilderness attack resolve/refund before the reset, avoiding an accidental half-army initialization advantage. No native AI answer is substituted for a Jev answer.

The harness deliberately does **not** initialize `WinCheckExecution`: a human holding 2,500 tiles against an 80/100-tile target already owns >80% of this tiny prepared map, so a real WinCheck would declare a map victory before the combat question. The real `GameRunner`/`Executor` still executes every attack, native AI and construction tick. The 80-tile target is an intentionally unusual *already below elimination threshold* state; the 100-tile case shows crossing the strict boundary after taking one tile. These edge cases are not representative untouched nations. Trial horizon is **400 game ticks (40 simulated seconds)** after attack initialization. The report distinguishes `nation-conquest`, `human-eliminated`, `one-send-ended-without-conquest` (no remaining attack stack, target alive), and `censored-tick-cap` (a still-active attack at the horizon). In this run all 80 non-conquests had ended their one-send stack; none was merely censored. Neither label means future reinforcement could never conquer the target.

## Counterexamples measured in the actual engine

| Prepared target / send | Actual outcome | What it rules out |
| --- | --- | --- |
| **100 plains tiles**, 150,000 target reserve, no Post; **10% = 30,000** sent | Conquest after **1 combat tick**, target reaches 99 tiles and remainder is redistributed; native-AI version also completed before a counterattack | A send **smaller than defender reserve can finish** a near-eliminated target. Reserve comparison alone must not suppress every cleanup. |
| **500 plains tiles**, 150,000 target reserve, no Post; **40% = 120,000** sent | Conquest after **15 combat ticks**, 8,400-gold full-wallet transfer | The exception is not limited to an already sub-100 remnant: a smaller-than-reserve send can complete a larger target under these conditions. |
| Same 500 tiles / 150,000 reserve / no Post / **40%**, but target **mountain** terrain | Stack ended, **130 target tiles remain**, no conquest gold | Same reserve ratio is not same finishability; terrain and growing armies change the result. |
| Same 500 plains tiles / 150,000 reserve, **completed Post**, **50% = 150,000** sent | Stack ended, **354 target tiles remain**, no conquest gold | Even a send equal to the target's initial reserve is not a guaranteed finish. |
| **2,000 mountain tiles**, 50,000 target reserve, **completed Post**, **50% = 150,000** sent | Stack ended, **995 target tiles remain**, no conquest gold | A send **three times initial target reserve**, using the largest offered fraction, can still fail. |

The matrix had 105 conquests, including **45 with send < target's initial reserve**, and **15 non-conquests with send > target's initial reserve**. These counts are artificial-case coverage, **not kill probabilities or win rates**. Many successes are the deliberately thin 80/100-tile boundary cases. Successful conquest is credited at the real sub-100-tile trigger, not inferred from residual reserve or damage.

For the 500-plains/150,000-reserve/no-Post 40% example, `AttackExecution` actually called `Game.conquerPlayer` at **99 remaining tiles**. Target wallet was **8,400 gold**, human wallet 8,400; unchanged engine transfer left target gold **0** and human **16,800**, with `ConquestEvent.gold=8400`. The 2,000-mountain/Post failed 50% trial had **zero ConquestEvents/transfer**, and the target continued regenerating to 250,323 internal reserve by the final sample. The attack included **318 protected tile-logic calls** and 687 unprotected calls, so the Post did not cover every captured tile. Worker gold and ordinary regeneration continue during the trial and must not be called conquest reward or combat casualties.

## Native retaliation is observed, not assumed on every trial

In the matched **2,000-plains-tile / 300,000-target-reserve / no-Post** cohort, every fraction failed to conquer. With **native AI disabled**, the 50% send ended with 1,153 target tiles. With actual Impossible `NationExecution`, native AI queued an attack at game tick **146**, a real outgoing/our incoming attack appeared at tick **147** (77 ticks after the human attack was initialized), and the target finished with **1,421 tiles**. Its actual native counterattack stack at first observation was about **11,149 internal troops**, and the human one-send stack ended on that same tick. Other 20/30/40% members of that native cohort also had observed counterattacks; the 10% member did not. Overall **five of the twenty native-AI trials** had both queued and observed native attacks on the human. No counterattack is fabricated for a trial whose target dies quickly or whose reserve/timing gates never permit it. This constrained example is not a prediction of how fast a real map nation will retaliate.

All **185** legal human attacks changed the target's relation **Neutral → Hostile** and created an embargo **at initialization**, before conquest, including failures. `AttackExecution.ts:176-194` applies −100 relation on Impossible. `AiAttackBehavior.ts:262-388` prioritizes retaliation for Impossible, but its reserve/trigger checks (`:234-258,402-412`), relative-neighbor send caps and attack-size checks (`:914-989,1000-1040`), timing and geography still condition any action. Hostility is an observed cost of initiating the attack, not proof of an automatic counterattack or eternal hatred. See `docs/tribe-gold-and-nation-hostility.md` for relation decay and embargo limits.

## Why the ratio alone fails; what can be said to the model

`Config.attackLogic` (`src/core/configuration/Config.ts:872-960`) uses terrain magnitude/tile cost, target troops-per-tile, attack stack relative to defender reserve, attacker/defender territory bonuses and current border size. `PlayerExecution` keeps regenerating armies as tiles change. A completed defender-owned Post within radius 30 raises per-tile attacker-loss magnitude ×5 and time fraction ×3; `AttackExecution.ts:329-370` checks coverage per tile, not once for the whole nation. `AttackExecution.ts:432-460` triggers elimination only when target tiles are **strictly less than 100**, then redistributes remnants and awards the **whole remaining nation wallet** (`GameImpl.ts:1371-1453`, `Config.ts:724-733`). None of those mechanics is equivalent to “50% of us > target reserve means guaranteed conquest.”

The existing target territory/reserve and current attack stacks are source-backed facts; an observed near-elimination target and continued progress can inform a cleanup judgment. Terrain, exact Post coverage, usable land-border geometry, target regeneration and native counters need corresponding observations before being asserted in a model descriptor. The current experiment does **not** authorize adding unobserved future troop income or a hidden simulator search to Jev. Moritz's **credible whole conquest** remains a strategic judgment with uncertainty: keep tribe-phase/focus legality in the harness, preserve allowed 10–50% choices for nation cleanup when the phase permits, and do not silently force or veto a nation size from an arbitrary single army-ratio threshold.
