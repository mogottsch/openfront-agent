OpenFront: hybrid strategic agent and spatial understanding

Draft 1 · 23 September 2026 · architecture proposal, not a deployed change to the running bot. Source of truth: OpenFront game simulation and GameView. Reviewed with Almeida / Jev guidance.

Scope and hard boundaries

EXISTING Local prototype

Local solo game; Jev receives bounded land observations, selects wait or legal land attack, and a sidecar executes through normal intents. One-second single-flight pacing, stale-response rejection and logs exist. Latest committed land policy was neutral v3; the expanded neutral v3.1 menu and strategy-v4/v4.1 experiment are uncommitted. Earlier v4 play showed failed live wilderness behavior, with an initial bounded 30-decision v4.1 run showing seven 10% wilderness sends, 22 waits and one 10% tribe send; long-run strength remains unproven.

PROPOSAL Future hybrid

Map/structure observations, new build and upgrade intents, candidate site summaries, region-level planning, GitHub Copilot-backed LLM. Moritz authorized implementing these capabilities, but they are not yet in the live observation or action contract; introduce each only after targeted tests and bounded local matches. Image overlays are optional explanations, not execution coordinates.

NOT A CLAIM Competitive strength

No win-rate or hardest-bot result yet. A short successful model probe, legal intent, or seed-specific game is not proof of a competitive agent. First evaluate baselines and full matches.

Placement diversity and compute budget

Enumerate eligible territory/coast candidates in bounded chunks, cluster by region/front/water body, then retain Pareto-diverse sites for safety, connectivity, frontier coverage, and cost rather than the single maximum of a hand-written score. Include existing-structure upgrades and save gold. Cache slowly changing distances/coverage; limit expensive worker buildables checks and test time-per-snapshot on the largest map. Evaluate candidate recall against exhaustive placement on small maps and expert-labeled opportunities. The nation AI in NationStructureBehavior.ts is an informative baseline (border depth, spacing, connectivity, water components), not an optimal oracle or an undisclosed action policy.

External API boundary and credentials

Current Jev sidecar sends POST https://api.typesafe.ai/v1/systemone with server-side bearer credentials, structured state and typed questions; it parses Choice, enforces a single pending request and start-to-start ≥1 second. A Copilot planner connector is not yet specified: gh copilot on this host reports a preview CLI, not evidence of a stable, permitted Chat Completions endpoint or an API contract. Before implementation, verify the supported GitHub Copilot integration/API, authentication/terms, headless structured output, rate/cost, and timeouts. Keep credentials on the sidecar; no browser-held tokens. If no supported route exists, block the planner slice rather than scraping an internal endpoint or silently changing providers.

Runtime, memory and causality

  1. Capture one GameView snapshot; calculate and cache features with its tick/revision. Record legal candidate coverage before inference.
  2. Only on meaningful events or bounded review interval, send a compact summary to the Copilot planner. Maintain plan version/expiration. On invalid/stale output, use an unexpired, revalidated prior plan only under an explicitly tested fallback policy; otherwise issue no planner-driven action pending an agreed safe mode. The planner may run slowly; Jev must not block the ongoing game waiting for a new plan.
  3. At the bounded local-decision cadence, offer Jev an explicit branch Choice (wait plus every feasible action family). Code can exclude a branch only for objective impossibility, never to enforce a hidden priority. If Jev chooses a branch requiring site selection, recheck branch feasibility, plan version and snapshot freshness before offering candidates in a later non-overlapping call; restart selection if changed. The planner advises choices but does not preselect the branch. Preserve request-start ≥1 second, single-flight, no catch-up burst; test any new planner scheduler independently so it cannot race snapshots or exceed provider budgets.
  4. Resolve only the returned candidate ID; perform real worker legality, gold and ownership checks, then emit a normal event. Retain pending construction/upgrades to avoid paying repeatedly while outcomes lag.
  5. Observe subsequent game updates and associate them with the intent. Distinguish chosen answer, emitted intent, accepted construction, lost structure, and match result. Trigger replanning after significant changes, not merely every second.

Evaluation before changing policy

QuestionEvidence and comparison
Does the spatial layer find useful sites?Small synthetic maps with expected water/front/connection topology; exhaustive legal-placement recall on tractable positions; snapshot timing/memory. Compare with strongest nation structure placement and deterministic site ranking.
Do model judgments help?Retain exact state, instructions, options, model/version, probabilities/confidence, response latency, validation result, intent, later game state. Annotate failures: missing candidate vs wrong fact vs model preference vs execution race. Evaluate labeled held-out sites and A/B choices before prompt changes. Preserve the v4 wilderness-collapse trace as a regression case; a 30-decision v4.1 live run avoids that specific collapse but is not proof of a durable remedy or hardest-bot strength.
Does the hybrid win?Seeded complete matches on several maps and difficulties (including Impossible); multiple seeds/spawns, paired opponents, held-out tests. Compare scripted baseline, Jev-only, planner+Jev and existing nation AI on win rate, population, territory, economic output, structure survival, inference cost and latency. A full match outcome is different from a model call or intent.

Do not claim to beat the best bots until paired held-out games support it. Log run configurations and engine/model versions; keep generated logs and API credentials out of Git.
