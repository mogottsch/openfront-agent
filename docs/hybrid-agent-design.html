OpenFront: hybrid strategic agent and spatial understanding

Draft 1 · 23 September 2026 · architecture proposal, not a deployed change to the running bot. Source of truth: OpenFront game simulation and GameView. Reviewed with Almeida / Jev guidance.

Scope and hard boundaries

EXISTING Local prototype

Local solo game; Jev receives bounded land observations, selects wait or legal land attack, and a sidecar executes through normal intents. One-second single-flight pacing, stale-response rejection and logs exist. Committed land experiment v4.2 has reviewed priorities, a hard tribe ≤20% cap and real-action checks. v4 depleted reserves; v4.1 overcorrected with categorical waiting; v4.2 improved a paired 30-second Impossible opening, but a complete 5-minute Onion/Impossible Jev match lost: the human held only its 6,505-tile island after land options ended at second 46; winning nation Outer Enclave owned 109,234 tiles and built a City and two Defense Posts. City candidates are now connected in an opt-in local hybrid path, but Jev has not selected a live City build.

STAGED Hybrid extensions

Worker-checked City and coastal transport choices are now locally opt-in; Defense Posts, upgrades, richer region-level planning and a valid GitHub Copilot-backed objective remain next slices. Moritz authorized autonomous local development, but only tested, explicitly flagged interfaces enter live model input/actions; no multiplayer scope. Image overlays are optional explanations, not execution coordinates.

NOT A CLAIM Competitive strength

There is one complete real-Jev Impossible loss and 0/3 full wins for each scripted land/boat control. A model probe, legal intent or landed mock-selected boat is not a competitive win. Paired held-out full matches are still required.

Placement diversity and compute budget

Enumerate eligible territory/coast candidates in bounded chunks, cluster by region/front/water body, then retain Pareto-diverse sites for safety, connectivity, frontier coverage, and cost rather than the single maximum of a hand-written score. Include existing-structure upgrades and save gold. Cache slowly changing distances/coverage; limit expensive worker buildables checks and test time-per-snapshot on the largest map. Evaluate candidate recall against exhaustive placement on small maps and expert-labeled opportunities. The nation AI in NationStructureBehavior.ts is an informative baseline (border depth, spacing, connectivity, water components), not an optimal oracle or an undisclosed action policy.

External API boundary and credentials

Current Jev sidecar sends POST https://api.typesafe.ai/v1/systemone with server-side bearer credentials, structured state and typed questions; it parses Choice, enforces a single pending request and start-to-start ≥1 second. Both paid decision endpoints now require a short-lived token from explicit POST /session Start (and revoke via DELETE /session); the experimental hybrid route also defaults off unless OPENFRONT_HYBRID_EXPERIMENT=1. This is a local guard, not remote user attestation. An isolated planner connector now uses the official @github/copilot-sdk@1.0.15-preview.1, pinned on the Node sidecar, with no available tools or tool permissions; its structured-output API is still preview/runtime-gated. Early explicitly Started SDK attempts returned no validated plan; fixed-code and typed session.error diagnostics established GitHub authorization HTTP 403 in the SDK model turn, not a Jev prompt error. An SDK turn attempt alone is not proof of an upstream paid request. The Node service now requires explicit COPILOT_GITHUB_TOKEN (Copilot Requests permission) and suppresses ambient gh/CLI auth; without it the planner is disabled. Jev continued without an objective. No browser tokens, raw provider errors or undocumented endpoints. Keep credentials server-side and do not silently change providers.

Runtime, memory and causality

  1. Capture one GameView snapshot; calculate and cache features with its tick/revision. Record legal candidate coverage before inference.
  2. Only on meaningful events or bounded review interval, send a compact summary to the Copilot planner. Maintain plan version/expiration. On invalid/stale output, use an unexpired, revalidated prior plan only under an explicitly tested fallback policy; otherwise issue no planner-driven action pending an agreed safe mode. The planner may run slowly; Jev must not block the ongoing game waiting for a new plan.
  3. At the bounded local-decision cadence, offer Jev an explicit branch Choice (wait plus every feasible action family). Code can exclude a branch only for objective impossibility, never to enforce a hidden priority. Ask parallel branch, land-action and city-site Choices in one bounded TypeSafe request with explicit branch premises; discard unused answers rather than issuing sequential requests against changing snapshots. The planner advises choices but does not preselect the branch. After the answer, recheck branch feasibility, map/tick, candidate ID, plan version, worker legality and funds; discard stale choices instead of substituting actions. Preserve request-start ≥1 second, single-flight, no catch-up burst; test the new scheduler independently so it cannot race snapshots or exceed provider budgets.
  4. Resolve only the returned candidate ID; perform real worker legality, gold and ownership checks, then emit a normal event. Retain pending construction/upgrades to avoid paying repeatedly while outcomes lag.
  5. Observe subsequent game updates and associate them with the intent. Distinguish chosen answer, emitted intent, accepted construction, lost structure, and match result. Trigger replanning after significant changes, not merely every second.

Naval Choice decomposition under test

On a genuine core-engine Onion snapshot after 200 no-intent regrowth ticks (6,505 island tiles, 18,891/48,813 displayed reserves, 11 worker-checked wilderness coasts, zero omissions), one actual Jev request chose the boat_attack branch narrowly (0.51 versus 0.49 wait). Its separate flat 56-option site+size Choice chose wait (0.34; nearest-coast 10% option 0.16). No intent was emitted. A later probe timed out. Wait may be strategically reasonable; option dilution is a hypothesis, not a proven mistake.

A network-free alternative in src/naval-decomposed-policy.mjs keeps one TypeSafe request but asks an independent target Choice (11 IDs plus wait) and one speculative size Choice per target (wait plus legal 10–50%, tribe max 20%). Code consumes only Jev's selected branch, target and that target's size; any wait still waits. Tests cover stale/missing choices and 16-target bounds. With the revised v1.1 island guidance, serialized full11 requests are 36,977 JSON bytes flat versus 37,243 decomposed (13 small questions); the separately worker-checked deployed-size8 input is 28,005 versus 28,154 (10 questions). In three actual Jev calls on fixed genuine engine snapshots, full11 with healthy reserves chose branch → site8 → 10% (13,545 input tokens, 1,477ms); the same island before regrowth chose wait (13,429 tokens, 1,145ms); bounded8 after regrowth chose branch wait even though its speculative target answer favored nearest site1 at 0.94 (10,230 tokens, 921ms). No game intents were emitted by this probe. The earlier flat full11 request chose branch boat but action wait (13,841 tokens, 992ms). The prompts and candidate counts differ; these samples do not prove causal improvement, lower cost, competitive play, or reliable live boat behavior. The revised policy is probe-only until a separately flagged live test. No other provider/request retries are hidden.

Approval and implementation slices

0 · Land regression and opening

TESTED SLICE v4.2 no longer confuses a 30% reserve with a 30% send or treats every active push as a wait command. Paired real-model/engine 30-second Impossible openings recorded. One complete seeded Jev match lost; more full matches and demonstrated wins are needed. No spatial scope required.

1 · Read-only spatial topology

TESTED MODULE Cardinal regions, fronts, water components and geometric site prefilter exist with synthetic tests. On a 3.96M-tile test map, analysis took ~952ms and prefilter ~310ms; never place this on a one-second loop. City and worker-checked coast summaries can enter the opt-in Jev Choice; the exact raw tile map does not. A spatial debugging overlay remains future.

2 · City candidates, no model action

TESTED MODULE Worker-checked City sites with BigInt costs, opaque IDs, freshness and single-use validation are wired to the opt-in panel; real model input with four sites has been observed but no City intent. A read-only Defense Post adapter and source-grounded range/combat microbench are also complete, not yet model-facing. Upgrades and other building types remain future.

3 · Bounded build action

LIVE PATH, CITY UNOBSERVED Opt-in local Start Hybrid is wired to normal City intents through opaque IDs and fresh worker checks; one request asks parallel branch/land/site Choices. Early headed smokes had no affordable City. In a later controlled 1M-starting-gold local match, four real worker-legal City sites costing 125k each were offered to Jev in two actual three-Choice calls; it selected wait and save_gold twice. The City-capacity benefit (+25k display troops after 20 ticks) was computed from the engine and supplied, not invented by the model. There was no City intent, let alone an accepted construction or competitive win. Candidate omission counts and the unchanged model probabilities are logged locally.

4 · Planner integration

LIVE ATTEMPT FAILED Opt-in server-owned Copilot plan lifecycle, fresh heartbeat and minimal Jev projection are wired with a separate three-attempt application-level cap and shared model busy lock. Three Start-gated SDK attempts returned no validated plan; fixed-code/typed event diagnostics identified authorization HTTP 403 during send_and_wait. The service now disables planning unless a server-side COPILOT_GITHUB_TOKEN with Copilot Requests permission is configured; ambient gh/CLI fallback is disabled. Auth/seat/org policy require Moritz action before a new bounded attempt. No browser credentials. A planning call can pause Jev for up to 15 seconds; SDK-internal requests are not yet observable as separate provider starts.

5 · Expand and benchmark

FUTURE SLICE One actual-model full Impossible Onion match completed with a loss after the 6,505-tile island; no further land moves existed from second 46. Two no-model land controls each lost 0/3 full matches; an actual-engine two-boat control crossed water but also lost 0/3. A port-free boat intent landed off-island through a worker-checked adapter in a source-grounded explicit-mock run. Opt-in hybrid naval Choices and guarded normal intents are wired, but real Jev boat action/gameplay was not observed in short headed matches (TypeSafe HTTP 529 and stale slow replies). Scripted 10/20/30% wilderness boat sweeps all lost 0/3 full Impossible seeds. Next: stable TypeSafe response, authorized Copilot plan, model-chosen City/boat/Defense Post actions and complete seeded wins; prove held-out performance before a best-bot claim.

Decisions and unresolved questions

CONFIRMED Existing bot uses a local bridge and normal game intents; timing/legality are code-owned. Moritz authorized autonomous development of a hybrid Jev + Copilot-backed agent against hardest native bots, including spatial/building research. Exact spatial fields, supported provider transport and fallback behavior still require evidence; local solo scope remains unless separately expanded.

  1. D1 · Validate read-only spatial features first. Test geometry and candidate recall without granting building actions. Risk: computation and map update cost.
  2. D2 · Start with one building type. Tentatively city plus save-gold alternative after nation-AI economic baselines; choose by measured win impact, not easiest wiring.
  3. D3 · Verify Copilot connector before coding against it. Confirm concrete API/auth/terms; a preview CLI alone does not establish a supported headless API. No assumption of unlimited or free requests.
  4. D4 · How much autonomous agency and what fallback? Moritz authorized autonomous development toward beating the hardest bots. Roll out locally in tested slices: observe recommendations, then limited autonomous building; evaluate consequence-dependent confidence and connector-failure behavior before generalizing it.
